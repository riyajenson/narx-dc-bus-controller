# Model Design

## Why an LSTM?

A PI controller is dynamic: its output depends on the present error and the
accumulated history of previous errors. A static neural network receiving only
one row cannot reproduce that memory reliably.

A stateful LSTM provides temporal memory through its recurrent hidden state,
without feeding predicted controller outputs back as inputs. This avoids error
accumulation through a predicted-output feedback path.

## Signals

Let:

- `r(k)` be the DC-bus voltage reference
- `v(k)` be the sensed DC-bus voltage
- `e(k) = r(k) - v(k)` be the voltage error
- `u(k)` be the controller command

The learned controller approximates:

```text
u(k) = f(r(k), v(k), e(k), hidden_state(k-1))
```

The LSTM receives reference voltage, sensed voltage, and voltage error as
inputs. Its recurrent hidden state carries temporal memory without requiring
the predicted controller output to be fed back.

## Architecture

- Sequence input layer with 3 inputs
- LSTM layer with 64 units
- Fully connected layer with 32 units
- Tanh activation
- Fully connected output layer with 1 unit
- Regression output

Training uses Adam optimizer with learning-rate scheduling, gradient clipping,
and validation monitoring.

## Training Data

The final controller trains on 180 randomized synthetic DC-bus episodes
generated by a PI expert with anti-windup. Each episode randomizes plant time
constant, control gain, reference steps, load disturbances, and measurement
noise.

This synthetic data generation approach replaced the original-data-only
pipeline after fixed-window MLP, original-data LSTM, and plant-surrogate
attempts could not support a reliable deployable closed-loop controller.

## Data Splitting

Synthetic episodes are split by episode, not by individual shuffled samples.
This keeps each test episode unseen during training and better represents
future deployment behavior.

## Safety Constraints

The LSTM output is clipped to the same command limits used by the PI expert.
The final Simulink benchmark keeps PI and LSTM in parallel loops so both
controllers see the same reference and load disturbance.

## Rejected Alternatives

- **Fixed-window MLP on original data**: Negative chronological test
  R-squared; the bounded feature window could not reconstruct the PI
  controller's internal state.
- **Original-data LSTM**: Negative chronological test R-squared; the supplied
  logged data did not include enough plant and operating-state information.
- **ARX plant surrogate**: Negative free-run R-squared; the data-driven plant
  surrogate could not support reliable closed-loop experiments.

These failures demonstrate why the final approach uses synthetic data
generation with a known plant model.

## Limitation

All successful closed-loop results apply only to the simplified first-order
synthetic benchmark. They do not establish switching-converter, hardware, or
original-system performance. The original DC-bus Simulink plant was not
supplied.
